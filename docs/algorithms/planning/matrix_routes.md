## 什么时候选择路线

车辆必须在地图上、有目标，且处于 TO_PICKUP、TO_DROPOFF 或 RETURNING。当前计划为空，或连续等待达到 `replan_wait` 时，算法重新选择路线；其他车辆保留当前计划。

## 候选生成与缓存

按 `(起点格点 ID, 目标格点 ID)` 缓存候选集合。同一地图下再次遇到相同起终点时，若候选仍在 LRU 缓存中则复用；更换地图时清空缓存。

首次生成时，执行 `candidate_count` 轮路径搜索：

1. 用当前惩罚表搜索一条路径，第一轮惩罚表为空。
2. 路线尚未出现过时，加入候选集合。
3. 对本轮路线经过的每个格点累加 `diversity_penalty`，供下一轮搜索使用。

这里的惩罚用于生成多样路线，独立于评分时的占用特征。即使本轮找到重复路线，仍会累加惩罚。最终不同候选数最多为 `candidate_count`，不保证恰好达到该数量，也不保证是严格的前 K 条最短路径。

`diversity_penalty = 0` 时，多轮确定性搜索可能始终得到相同路线，去重后只保留一条。公共寻路函数仅在已经到达目标时返回空路线；不可达时抛出包含起终点 ID 的异常，终止本次规划，不把不可达路线当作 0 分候选。HTTP 世界进入失败状态，批量作业记录错误。

## 特征与评分

为本次需要规划的车辆汇总所有候选，每条候选形成一行特征：

```text
[路线步数, 路线上被其他车辆当前占用的格点数]
```

占用特征在每次评分时根据当前快照重新计算，不随候选路线一起缓存。评分为：

\[
\operatorname{score}(r)
= \operatorname{distance_weight}\,|r|
+ \operatorname{occupancy_weight}\,\operatorname{occupied}(r)
\]

其中 \(|r|\) 为路线步骤数，`occupied(r)` 为路线中被其他车辆占用的格点数。每辆车选择自己候选中得分最低的一条，替换当前移动计划；得分相同时保留候选生成顺序中最早的一条。

## 参数

| 参数 | 类型 | 默认值 | 允许范围 | 作用 |
| --- | --- | ---: | --- | --- |
| `candidate_count` | int | 4 | 1–32 | 候选生成的搜索轮数，也是不同候选数量上限 |
| `replan_wait` | int | 4 | 1–10000 | 连续等待达到多少 tick 后重新选择路线 |
| `diversity_penalty` | float | 3.0 | 0–1000 | 后续搜索对已用格点累加的代价 |
| `distance_weight` | float | 1.0 | 0–1000 | 路线步数的评分权重 |
| `occupancy_weight` | float | 8.0 | 0–1000 | 当前占用格点数的评分权重 |

参数解析、错误回退和应用方式见 [公共规则](../common.md#可配置参数)。两个评分权重同时为 0 时，所有候选同分，选择最早生成的一条。

## CPU/CUDA 分工与边界

路线生成、缓存和特征提取均在 CPU。注册器注入所选计算后端，只把特征矩阵的加权评分交给 `backend.score()`；直接构造算法且未传后端时使用 CPU 评分器。CUDA 不可用或运行失败时按后端规则回退 CPU。

每辆车独立选择最低分路线。当前占用不等于未来占用，没有多车联合预约或完成率保证；CUDA 路线评分也不等于整个仿真在 GPU 上运行。

## 候选缓存预算

候选集合以不可变 tuple 保存，按 [资源配置](../../../config/resources.py) 的 `MATRIX_ROUTE_CACHE_MIB` 限制，默认 128 MiB。LRU 计费包括键、路线容器、条目包装和索引增长；Cell 由地图共享，不重复计费。固定空缓存对象开销不计。预算不足时淘汰最久未使用的起终点组合；单个集合超预算时不保留，但仍参与本次评分。命中会续期，淘汰只影响重新生成的计算量，不改变该起终点的确定性候选生成与评分规则。

缓存预算只约束跨调用保留的数据。本次批量规划中尚需评分的候选、特征矩阵和输出计划另占内存。
