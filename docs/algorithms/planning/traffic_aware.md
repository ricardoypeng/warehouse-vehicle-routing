# TrafficAware：按当前占用重新规划

类别：planning。选择 ID：`traffic_aware`。

[返回算法目录](../README.md) · [公共协议与参数规则](../common.md)

实现和参数声明见 [TrafficAware](../../../algorithms/planning/standard.py)，带惩罚的路径搜索见 [公共寻路函数](../../../algorithms/common.py)。

## 什么时候重新规划

车辆必须在地图上、有目标，且处于 TO_PICKUP、TO_DROPOFF 或 RETURNING。满足以下任意一项就生成替换计划：

- 当前计划为空。
- `wait_ticks >= replan_wait`，连续等待达到阈值。

未达到阈值且已有计划时，保留剩余计划。规划器只提交路线，是否真正移动仍由内核仲裁。

## 路径代价

把其他车辆当前占据的格点加入惩罚表，自己的格点不加占用惩罚。每次进入相邻格点的代价为：

\[
1 + \operatorname{penalty}(\text{neighbor})
\]

其中，被其他车辆占用时 `penalty = occupancy_penalty`，其他格点为 0。Dijkstra 根据这个代价选择路线，输出不包含起点的移动步骤。

因此算法会权衡绕路步数和经过已占格点的代价。占用格点仍可作为候选路径的一部分；惩罚不是禁止通行。

## 参数

| 参数 | 类型 | 默认值 | 允许范围 | 作用 |
| --- | --- | ---: | --- | --- |
| `replan_wait` | int | 3 | 1–10000 | 连续等待达到多少 tick 后重新规划 |
| `occupancy_penalty` | float | 8.0 | 0–1000 | 进入其他车辆当前格点的额外代价 |

参数解析、错误回退和应用方式见 [公共规则](../common.md#可配置参数)。惩罚为 0 时路径代价退化为步数，但持续等待触发重新规划的行为仍保留。

## 状态与边界

没有跨 tick 的路线缓存。每次需要重规划时，从当前快照重新构造惩罚并搜索。

惩罚只反映当前占用，没有预测车辆下一步位置，也没有多车未来预约表。多车可能同时选择相同路线；持续等待还可能导致反复规划。该方法改善路线选择的依据，但不保证任意负载下无死锁或最短完成时间。

不可达目标会由公共寻路函数显式抛出异常，并报告起终点 ID；已经到达目标才返回空路线。HTTP 世界进入失败状态，批量作业记录错误。
