# ShortestPath：有向最短路线

类别：planning。选择 ID：`shortest_path`。

[返回算法目录](../README.md) · [公共协议与参数规则](../common.md)

实现见 [ShortestPath](../../../algorithms/planning/standard.py)，路径搜索见 [公共寻路函数](../../../algorithms/common.py)。

## 什么时候生成计划

每次 `update()` 检查车辆，同时满足以下条件才生成替换计划：

- 车辆在地图上，当前位置和目标都存在。
- 执行阶段为 TO_PICKUP、TO_DROPOFF 或 RETURNING。
- 当前移动计划为空。

已有非空计划会继续保留。车辆因冲突而受阻时，单纯等待不会触发该算法重新规划。

## 路径规则

调用 `path(current_cell, goal, distance=junction_cache(world.map).distance)`，沿格点的有向 neighbors 搜索。公共函数以单位步数累计已走代价 \(g\)，用当前地图的静态有向最短路距离作为 A* 启发估计 \(h\)。静态距离与 \(g\) 同口径且一致，因此返回的仍是道路步数最少的路线。

返回路线不包含起点，第一项是车辆下一步要进入的格点，再包装成 `MovementPlan` 提交。已经位于目标或缺少端点时，公共函数返回空路线；有起终点但不可达时抛出包含格点 ID 的异常。到达后的装卸状态转换由内核处理。

## 状态与参数

没有实例级路线缓存和可配置参数。搜索复用按地图共享的静态路口距离表，不保存具体路线。非空计划由车辆持有，并由内核逐步消费；它不属于算法内部缓存。

## 适用边界

规划只考虑静态有向地图，不考虑当前占用或未来预约。多辆车得到的最短路线可能相互阻塞，冲突安全由内核仲裁保证。最短路线不保证多车场景一定完成，也不保证总等待时间最少。

不可达异常使 HTTP 世界进入失败状态，批量作业记录错误。
